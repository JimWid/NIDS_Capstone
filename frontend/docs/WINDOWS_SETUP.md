# First run on Windows — Daniel's setup

You already have VS Code, Git, Node/npm, WSL and a successful Docker hello-world test. Use `npm.cmd` in PowerShell to avoid the `npm.ps1` execution-policy error. You do not need to relax that policy.

## 1. Extract and copy

1. Download `NIDS_Dashboard_Frontend.zip` and select **Extract All** in Windows Explorer.
2. Inside the extracted folder is a folder named `frontend`.
3. In VS Code, right-click your repository's `frontend` folder and choose **Reveal in File Explorer**.
4. Copy the **contents** of the extracted `frontend` into the repository's existing `frontend` folder. Replace the old Dockerfile only if it is still the empty placeholder. If teammates have since edited any files, compare and merge those changes instead of overwriting them.
5. Confirm that the final path is `NIDS_Capstone\frontend\package.json` — not `frontend\frontend\package.json`.

## 2. Open the correct terminal folder

Your terminal may default to `C:\Users\danny`, even with the repo open. The easiest method is to right-click the repository's **frontend** folder in VS Code and choose **Open in Integrated Terminal**.

If you used the earlier clone instructions, you can instead run:

```powershell
cd "$HOME\Projects\NIDS_Capstone\frontend"
```

Check the folder:

```powershell
Get-Location
Test-Path package.json
```

The second command should print `True`.

## 3. Install the project dependencies

```powershell
npm.cmd ci
```

Allow the install to finish. This downloads the versions listed in `package-lock.json`. Each teammate runs this once after cloning, and again when the lockfile changes. Do not commit `node_modules`.

If `node` becomes unrecognized in a new terminal because fnm is not initialized, resolve the fnm shell setup before running these commands; do not install a second Node manager over it blindly. `node -v` and `npm.cmd -v` must work in the terminal you use.

## 4. Start the dashboard

```powershell
npm.cmd run dev
```

Leave this terminal running, then open:

http://localhost:3000

You should see **Network overview** and a **Demo mode** banner. Try:

- Devices → filter authorization to Unknown.
- Connections → search `192.168.1.47`.
- Alerts → filter severity to High → select an alert.
- In the alert dialog, select Explain this alert → Send.
- Export CSV from a filtered table.
- Resize the browser to check the compact layout.

Example assistant responses are intentionally labeled scripted. They are not generated by an LLM.

To stop the dashboard, click its terminal and press **Ctrl+C**. If prompted to terminate the batch job, enter `Y`.

## 5. Test the build

Stop the dev server, then run:

```powershell
npm.cmd test
npm.cmd run build
npm.cmd start
```

Open localhost:3000 again. This checks the production version. Stop it with Ctrl+C before trying Docker.

## 6. Test Docker independently

Open Docker Desktop and wait for its engine. From `frontend`:

```powershell
docker compose -f compose.demo.yml up --build
```

Open localhost:3000. This tests the frontend container without needing the rest of the NIDS. The first build downloads its base image and packages.

Stop with Ctrl+C, then:

```powershell
docker compose -f compose.demo.yml down
```

Do not run the repository-root Compose setup yet unless the backend and detection teammates have finished their service setup.

## Troubleshooting

| Symptom | Next step |
|---|---|
| Cannot find package.json | Your terminal is in the wrong folder. Use Open in Integrated Terminal on frontend. |
| npm.ps1 scripts disabled | Use `npm.cmd`, not `npm`. |
| Port 3000 is busy | Stop your other dashboard process/container, or run `npm.cmd run dev -- --port 3001` and open localhost:3001. |
| Docker daemon unavailable | Open Docker Desktop and wait for Engine running. |
| Backend unavailable | Stay in demo mode until the real backend is ready, or check the API address and documented endpoint contract. |
| Files changed but Docker page did not | Rebuild with the same Compose command. Source is copied into the image; it is not mounted for hot reload. |
| Real mode still shows Demo mode | Set `NIDS_DATA_MODE=api` in frontend/.env.local for npm, or in the container environment for Docker, then restart. |
| Need to undo configuration | Delete or edit frontend/.env.local, then restart. Demo is the default. |

## 7. Share through Git after testing

In the repository root, verify your branch:

```powershell
cd ..
git branch --show-current
```

If you are still on main, create a branch:

```powershell
git switch -c feature/dashboard
```

If that branch already exists, switch to it with `git switch feature/dashboard` instead.

Then review the frontend changes:

```powershell
git status
git add frontend
git diff --cached --stat
```

Check that no `.env.local`, `node_modules`, `.next`, PCAP files, credentials or model files are staged. When satisfied:

```powershell
git commit -m "Add local NIDS dashboard frontend"
git push -u origin feature/dashboard
```

Open a pull request and have a teammate review before merging. No GitHub pushes were performed on your behalf.
